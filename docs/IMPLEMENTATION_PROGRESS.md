# 非数字孪生版本实施记录

本轮优先完善地点别名和开放时间、道路方向和通行时间、两种路径策略、知识检索证据。保留现有数据与接口，暂缓数字孪生导入和三维仿真。

## 已核实的现状

- 管理端已有地点、路段、任务、知识和实景素材 CRUD，后端使用 JPA / MySQL。
- 现有导航已有 Dijkstra、关闭道路过滤、无障碍过滤和成功规划历史，无需重复建设。
- 当前 MySQL 业务接口中有 8 个地点、9 条道路、5 条知识。这些包含名称带【测试】的联调记录，不代表已核验的真实校园信息。
- 校园助手没有配置外部大模型；原检索逻辑会因单个汉字重合匹配知识，且没有过滤过期/待审核资料。

## 本批完成

1. 地点增加 `aliases`（中英文逗号、分号、顿号分隔）和 `openingHours`。管理端可维护、搜索，手机端展示开放时间与入口。新建地点不再预填虚构坐标。
2. 道路增加 `bidirectional` 和 `travelSeconds`，管理端可维护。长度必须大于零，起终点不可相同，后端校验合法状态和必填字段。
3. 规划请求增加 `optimization`：`DISTANCE` 严格按距离，`TIME` 按预计耗时；旧调用不传时默认 DISTANCE。受限道路的耗时增加35%，关闭道路始终排除。
4. 预计时间优先使用人工录入的秒数，否则按75米/分钟估算；不宣称实时 ETA。历史记录保存本次策略。
5. 导航识别地点别名，检查目的地开放状态；多地点需求暂时明确提示，不再悄悄忽略中间目的地。
6. 管理端路网图、手机导航页拓扑依据数据库连接关系绘制；它们是连接示意，不是地理地图。结果变化时更新对应路段高亮。
7. 知识检索排除过期和未发布资料，使用词组/双字匹配代替单字匹配。返回知识正文、来源、更新时间、有效期；知识命中也计入成功咨询。
8. 网页首页和手机助手展示来源与实际路线步骤，明确标识规则检索版；没有接入大模型。评分为内部启发式分数，不代表经校准的准确率。
9. 接口业务错误返回可读消息；地点加载失败清空旧数据并显示错误。手机支持刷新地点、路段和素材，修改条件或规划失败后不保留旧路线。

## 验收结果

- 后端15项测试通过：原有功能、时间/距离策略差异、单行路逆行拒绝、封路后重规划、别名解析、关闭目的地拒绝、无障碍过滤、多地点提示、同起终点、知识过滤与排序、H2数据库保存后重读与历史策略记录。
- 网页生产构建通过；手机端 TypeScript 检查与 Expo Android 导出通过（669个模块）。导出不等于安装包或真机验收。
- 本机运行健康检查为 UP，数据库类型为 MySQL；Vite 的 /api 代理可读取8个地点。
- MySQL实际接口验证：东门 → 校园卡中心420米、预计6分钟；自然语言“从东门去图书馆，避开施工道路”返回1360米路线及分段结果。
- 校园问答接口返回 RULE_BASED 模式和知识来源；空起终点、零长度/同节点道路被400错误拒绝。
- 验收使用现有测试记录；没有运行批量导入、清空、去重脚本。成功规划和问答按正常业务写入使用日志。
- 本轮未进行浏览器目视验收或手机真机操作；构建通过不等同于视觉验收。

## 查看方式

- 管理端：http://127.0.0.1:5173/
- 地点维护：http://127.0.0.1:5173/#/places
- 路网与路线测试：http://127.0.0.1:5173/#/network
- 后端健康：http://127.0.0.1:8088/actuator/health

先编辑地点填写别名和开放时间，再编辑路段填写方向与耗时。在路线测试页对比两种策略；关闭路段后再次规划验证绕行。首页助手可查询校园卡办理或输入起终点。手机端需要单独启动 Expo。
